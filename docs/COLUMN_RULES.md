## 所有列共同遵守

1. **事实有来源，计算有公式，判断有理由，预测有明确假设。** 不按代码、公司名、行业印象、股价走势或资料缺失猜事实。没有可靠证据时保留缺失、待核实或原有历史状态，不为填满表格造数。
2. 核实证券身份、股份类别、币种、单位、报告期间和日期。公司改名、ticker变更、拆并股及ADR比例必须核对。CSV是成员、名称、业务短标签和所选ETF的唯一入口，React不维护另一份逐公司映射。
3. 使用本项目已接受的数据源：行情用Yahoo/yfinance；公司经营、融资、治理事实优先SEC、公司IR、交易所及监管原文；ETF实际持仓用基金发行商。搜索结果与结构化字段可作线索，不能替代必要的原文确认。
4. 区分**行情日、财报/事实日、持仓截至日、研究完成日、抓取日、文件生成时间**。下载成功不等于研究完成；日常行情生成不续期研究、名单或ETF核查日期。
5. `null`/缺字段、真实数值`0`、不适用、请求失败、历史不足和已过期不能互换。缺数不判安全，不把失败判停牌；旧研究保留日期及缺口，不伪装成今日已核查。
6. 金融数值只在Python数据层计算。前端核对身份、版本与基准，负责展示、日期时效提示及排序；数据错误或版本不合显示不可用，不用推算补齐。
7. 每次新增或修改列、子行、角标或详情数据，**同时更新本索引与专项规则**，说明来源字段、人工入口、公式/判断、单位、日期、频率、缺失/失败/过期处理和验证方法。改变已接受的公式、来源、窗口或JSON契约仍走原有CR流程。

| --- | --- |
| 股票／形态、窗口、宽转窄 | CSV身份；60/90/120/252交易日并行回顾，优先合格近期窗口；已验证/严格待观察/突破/跌破/过慢/未成形/资料不足分别保留理由。宽转窄需满足文档中的包含和高度比例条件，不能凭肉眼写已验证 |

| 箱体位置 | C在所选L/U之间的线性位置，越界不截成0/100；不是主表252条52周位置 |
| 长期位置／一年涨幅 | 最近4个自然年的可用复权high/low区间位置；一年涨幅用252交易日前收盘，需253条。短历史必须明示；不是主表“今年涨跌幅” |
| 长期过滤及较一年低点涨幅 | 长期位置≥80%、一年涨幅≥100%或较最近252条低点上涨≥200%任一触发排除箱体候选，保留原形态及理由；不删除活跃成员。短历史按实际数据明示，不编完整四年 |
| 日／周K、OHLC与成交量 | 同次近5年历史；日线复权OHLC按Adj Close/Close派生，volume保持原始值，缺失null、真实0保留；周聚合方法及异常日处理按指标定义。不能修造缺价或补假成交量 |
| 两年RSI预览及箱体RSI副图 | 全历史Wilder预热后截取两年；箱体日线复用同批RSI按日期对齐。前端不重算RSI，文件身份/口径/版本不匹配则不可用，不能显示旧批走势冒充当前 |
| 单股业务、ETF、融资、治理、波幅 | 复用前述同一来源和门禁，不在箱体内另造评级/ETF归属。候选表保持形态数据，业务及研究只在单股详情 |

| 展示项 | 当前生成规则与维护要求 |

## 以后每次更新的执行清单

1. 先确认用户范围、CSV身份及当前规则；按本表列出哪些属于每日计算、哪些属于人工研究，不因“更新页面”顺带扩大隐藏池研究。
2. 对每一列记录本轮“已更新／复核后维持／未处理／缺证据／失败／不适用”，并保留原文、事实日期及实际覆盖；未处理不能算已复核。
3. 名称/业务/ETF/融资/风险等事实先查证；估值参数区分事实与显式预测；全部金融计算引用既有函数和专项公式，不临时猜数、换窗口或用另一列补空。
4. 同步唯一输入及其生成快照，检查code/symbol、口径、日期、单位、缺值、别名、零值、短历史及来源/版本门禁。ETF执行`python scripts/validate_sector_etfs.py`。
5. 数据/功能变化完成Python、lint/build、浏览器及必要真实行情验证并记录发布；**仅整理文档时检查规则与实现、相对链接及变更差异，不为文档整理刷新行情、研究日期或虚称重新尽调。**
6. 把本轮变化、维持理由、未核项和验证证据写入研究报告及CHANGELOG/OPERATIONS；如变更口径，同步需求/CR和本索引。历史快照只作证据，不作当前规则入口。
