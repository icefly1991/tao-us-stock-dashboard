# 每周基本面研究：字段清单与自动发布边界

CR-024。用户要求每周机器扫描并发布基本面研究，并限定只用免费规则、不接付费文本模型。本文件列出全部受影响的仓库字段与实际自动覆盖。**结构化财报初筛和新申报提示会自动发布；原文语义结论不能用免费字段可靠替代，继续保留旧结论并标“待判”。**

## 范围清单

| 研究维度 | 当前唯一来源 / 输出 | 页面 | 自动更新需要的证据 |
| --- | --- | --- | --- |
| 业务短标签 `business` | `scripts/stock_list.csv` → dashboard/boxes | 持仓、活跃、高风险池及详情 | 公司最新业务原文；改CSV会影响每日行情输出，不能仅凭SIC改写 |
| 资金等级 `grade`、标签、理由、现金覆盖 | `pool_review_overrides.json` + SEC事实 → `pool-review.json` | 高风险股票池及箱体详情 | 同期可比财报、可动用现金/短期投资、债务与后续融资；算法和人工覆盖冲突须显式报告 |
| 经营类型 `category`、理由与资料缺口 | `pool_categories.json` + 规则默认 → `pool-review.json` | 高风险股票池及箱体详情 | 主营业务阶段、商业化、收入性质及原文依据；无可靠证据保持“类型未核实” |
| 财务事实 `facts`、行业描述、地区 | SEC XBRL/原文 → `pool-review.json` | 基本面详情、摘要生成 | 币种、报告期间、申报日、原始链接和主体身份；不可混期 |
| 亮点/风险短语 | `pool_briefs.json` + 财报规则 → `pool-review.json` | 股票池两列、箱体详情 | 新原文与可比数字；每项独立来源，旧短语不可无证据沿用为本周新结论 |
| 治理覆盖、报告日期、事件、法律状态 | 覆盖清单 + `governance_events.json` → `governance-review.json` | 三个主表标记、筛选及两箱体详情 | 定期报告、8-K/6-K、交易所及公司IR公告；区分披露/调查/指控/裁定、当前/历史/解决 |
| 生存/退市风险 `distress` 与复核日 | 治理事件中人工标记 → `governance-review.json` | 三主表快捷筛选、两箱体详情 | 明确持续经营、上市或核心业务影响；没有新申报不能解除旧风险 |
| 研究日期与扫描日期 | 独立研究JSON / 周度扫描报告 | 基本面及风险日期提示 | 只有本周结论完成覆盖检查时更新`reviewed_at`；扫描成功只更新`scanned_at` |

每周自动文件为`public/data/weekly-research.json`：从SEC submissions检查344个公司/基金主体，从companyfacts检查234只高风险池的结构化财务事实。相对上次人工研究和上次成功周度扫描，只展示**新**财务事实、机器初筛等级、数字短语及新申报；同一申报号不重复当作本周新证据。Form 25及8-K的1.03/3.01/4.02条款只触发“须核实”关注点，不自动判定已破产、已退市或财报造假。完整下载/解析失败则不发布新文件。

当前快照：高风险池234只，类型原文覆盖82只、资金人工覆盖80只、短语人工覆盖130只；治理覆盖350只，78个代码88条事件。业务短标签覆盖全350只，不能因为只有234只在高风险池就漏掉其他116只的业务描述。

**不在本任务中改动**：股票池成员及A/B/C分档、名单维护日期、股价和日线指标、箱体筛选与行情生成日期。这些不是基本面研究输出。

## 自动发布门禁

1. 每周扫描要覆盖已核实CIK的344个公司/基金主体；6个非公司资产明确不适用。SEC之外的交易所、法院、IR来源要有独立覆盖或明确缺口。
2. 每家公司每个自动结论必须有官方原始链接、披露/报告日期、方法版本及证据状态；模型回答不能替代原文。财务事实须同期间同币种；风险事件不能从关键词或通用风险因素段落直接升级。
3. 新公告中若有无法解释的事项，保留上一次结论并标记“新资料待判”，不得把旧评级重标成本周已复核；失败和不适用不能计成功。
4. 旧重大/观察风险只有新证据明确解除时才能降级；无新文件、模型沉默、请求失败或冲突均不能解除。新重大风险需要可定位的原文与明确触发条件。
5. 生成完整研究JSON后校验成员数、必填字段、HTTPS来源、日期、人工与机器结论差异及前端契约；门禁失败时不覆盖有效Pages文件，保留失败报告。
6. 定时任务可延迟或失败；“每周更新”指每周尝试完整扫描与发布，页面必须区分本周已完成复核、无新证据、待核、失败和旧快照。

执行链：`scripts/scan_research_weekly.mjs`下载申报与XBRL，`scripts/build_weekly_research.py`复用已有Python初筛和短语规则，页面在原人工结论旁展示本周机器层。工作流通过自动提交独立周度JSON并部署Pages，使次日行情部署继续包含本周结果；不改`pool-review.json`、`governance-review.json`或CSV人工源。仓库Secret `SEC_CONTACT_EMAIL` 已配置，Linux 回归检查已通过；首次真实SEC端到端扫描及Pages发布仍须验证，完成前不应宣称任务已上线。
