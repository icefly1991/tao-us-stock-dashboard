# 基本面分类与风险提示：判定路径

## 适用范围

本页解释当前股票池研究快照（研究日 2026-09-27）的**已实现规则**。它不是实时评分或破产概率。

## 阅读提醒

行情每日刷新不会重新研究公司。财报规则是初筛，原文专项核查可以覆盖它；不能把下方初筛步骤直接当作最终页面等级。规则背景见 [股票池研究](POOL_RESEARCH.md) 和 [生存风险核查](FINANCIAL_DISTRESS.md)。工程复现步骤见[研究维护](RESEARCH_MAINTENANCE.md)。

## 资金等级的实际规则顺序

财报事实提取（代码 `extract_facts`）从已下载 SEC companyfacts 中选同一经营现金流报告期、同币种、截至研究日已申报的收入、净利润、经营现金流、现金、流动资产/负债和融资数据。事实保留期间、申报日及原文链接。资金初筛（代码 `classify`）按下面顺序返回首个命中结果：

```text
行业需专门口径？→ unknown
  否 → 必要字段缺失或报告期过旧？→ unknown
  否 → 负经营现金流 + 流动资产覆盖<12月 + 融资净流入？→ pressure
  否 → 收入/利润/经营现金流均正？→ 流动负债>流动资产则 watch，否则 supported
  否 → watch
  最后 → 有原文专项核查时，以有来源的人工等级覆盖初筛
```

1. SIC 60–65 或 67 开头的金融、保险、投资及地产结构，返回 `unknown`，等待专门口径；通用现金消耗模型不适用。
2. 缺经营现金流基准，或收入、利润、经营现金流、现金任一缺失，返回 `unknown`。基准期末距研究日超过 200 天，也返回 `unknown`。
3. 经营现金流为负、流动资产按该期间消耗速度折算覆盖不足 12 个月，且同期融资现金流为正，返回 `pressure`。**这是现行漏判点**：融不到资金而融资现金流非正的公司不会命中。现有人工覆盖还可能把满足三个条件的公司最终列为 `watch`；复核必须逐只看原文理由。详见[拟议变更](CHANGE_REQUESTS.md)。
4. 收入、净利润、经营现金流均为正：如同日流动负债大于流动资产，返回 `watch`；否则返回 `supported`。
5. 其余返回 `watch`。页面的现金覆盖月数只用现金及等价物，按同一经营现金流期间折算；规则 3 用的是全部流动资产，包含应收和存货。两个估算不能互换，均不含资本开支、债务和后续融资，也不是存活期限。当前数据未统一提取可动用短期投资，因此不能直接声称规则 3 已采用“现金加短期投资”。

人工原文核查可覆盖上述等级，但必须有等级、来源和同研究日证据；`review_method` 区分“财报初筛”和“原文专项核查”。覆盖可以替换过时的缺字段标签。类型的人工覆盖必须有合法类型、理由和 HTTPS 来源；无覆盖时统一为 `unresolved`（类型未核实），不再从资金等级推断业务阶段。当前 234 行中 152 行为默认类型，人工核实类型保留。金融、数字资产和披露风险类型不显示通用现金覆盖月数。

### 数字阈值与局限

| 阈值 | 当前用途 | 依据及待修事项 |
| --- | --- | --- |
| 流动资产覆盖 12 个月 | 资金压力初筛的一项必要条件 | 项目 V1 启发式阈值，尚未按偿债能力回测；流动资产不等于可用现金 |
| 报告期末距研究日 200 天 | 结构化事实过旧则初筛 `unknown` | 项目 V1 启发式阈值，并非 SEC 的统一申报期限；对 20-F/6-K、40-F 及错位财年可能误伤，须读最新原文补查 |
| 现金覆盖 24 个月 | `watch` 行增加“现金覆盖较长”标签 | 只依赖历史经营消耗，非资金安全红线 |

当前提取器允许 10-Q、10-K、20-F、40-F、6-K 结构化事实，但不保证 6-K 附件含完整可比 XBRL。200 天仅触发补查，不应把外国发行人的报告周期判成业务风险。`supported` 的准确解释限于“所选报告期收入、账面利润及经营现金流为正，且未在初筛中发现流动负债缺口”；它未校验债务到期、利息覆盖或一次性收益，不能称全面财务稳健。Nareit 对 REIT 的 FFO 有专门定义，[说明见此](https://www.reit.com/glossary/funds-operation-ffo)；但本系统尚未实现 REIT、银行或基金的统一专门算法。

## 风险提示的实际规则顺序

治理事件人工记录 `kind`、事实描述、披露日期、来源、`state`（当前/历史/已解决）、`legal_status`（披露、调查、指控、认罪、裁定等）及严重程度。严重程度本身**不触发**生存风险；内控、高管或控制人事件也不能直接等同公司危机。只有经过原文核查并明确涉及生存、上市、严重财报、融资或核心业务影响的事件，才人工赋 `distress: major/watch`。

汇总只看 `state=current` 且有 `distress` 的事件：覆盖不适用 → `not_applicable`；任一 `major` → `major`；否则任一 `watch` → `watch`；覆盖不可用 → `unknown`；其余 → `not_flagged`。历史及已解决事件仍在详情中，但不进入当前汇总。`not_flagged` 只表示本次初筛没有触发已列事件，不能当成安全评级。重大风险快捷筛选只改变显示范围，不删除成员。

| 原文证据示例 | 建议分层 | 复核重点 |
| --- | --- | --- |
| 公司明确披露持续经营重大疑虑仍未消除 | `major` | 后续融资是否已经完成、原疑虑是否由新报告解除 |
| 交易所作出普通股退市决定，尚在上诉或缓期 | `major` | 决定、上诉和交易状态分开记录；不能写成已退市 |
| 仅收到合规警告、可在期限内整改 | `watch` | 截止日及后续恢复合规公告 |
| 资金消耗依赖未来融资，但未有正式持续经营重大疑虑 | `watch` | 已签融资与仅计划融资、可用现金及到期债务 |
| 核心业务许可证被暂停且足以影响持续经营 | 需专项判断，可能 `major` | 暂停范围、期限、收入依赖及公司应对；普通监管调查不自动触发 |
| 高管被指控、内控缺陷或历史旧案 | 不自动标生存风险 | 法律状态、是否涉及公司本体与当前经营 |

这是**未来复核的判例指引**，不是对未核查公司自动套用的规则。当前事件记录没有独立“触发条件”字段；只有 `kind`、标签、详情和原文来源，尚不足以强制跨复核人一致。生成器为每条 `current` 事件安排研究日后30天的行政复核日期；页面逾期提示，但不能据此自动判定事件已解决。下一轮需逐只确定事件驱动的复核节点及触发条件。

## 快照检查结果（2026-09-27）

现有 234 只池：最终等级 `supported` 53、`watch` 167、`pressure` 13、`unknown` 1；25 只 SIC 60–65/67 标的最终均经人工等级覆盖，因此“当前金融类大量 unknown”不成立，但它们仍缺统一专门算法。当前快照中没有 `supported + major` 或 `operating + pressure`，不代表今后不会出现。EYPT、RGNX、SOC 的结构化事实满足现行流动资产覆盖不足 12 月且融资净流入为正的初筛条件，最终均为人工 `watch`；更改自动条件不能替代对这些覆盖理由的逐只复核。现金覆盖不足12个月逐只清单见[2026-09-29复核报告](reviews/2026-09-29-pressure-diff.md)：55只，仅是待核线索。

## 复核与修改

逐只核对最新原始披露、事实期间、事件状态及正反进展。四条轴分别判断；若出现 `supported + major`、`operating + pressure` 等看似冲突组合，应出具复核清单，核对证据、日期与人工覆盖理由，**不能机械地强制两轴一致**。具体步骤见[研究维护](RESEARCH_MAINTENANCE.md)。

当前边界：尚未对全池完成可动用现金、未来 12/24 个月偿债、TTM 现金消耗及稀释的逐只核验；没有自动新闻监控。研究日之后的公告可能改变结论，不能把 2026-09-27 快照说成今日实时状态。
