# Architecture Decision Records

ADR 记录重要选择及其理由。已接受的决定若要改变，先在 `CHANGE_REQUESTS.md` 建立 CR。

## ADR-001：使用 yfinance 作为首版数据源

- 状态：Accepted
- 日期：2026-09-14
- 关联需求：DATA-001, DATA-002, NFR-002

### 决定

首版使用 yfinance 获取日线，不要求 API Key；`scripts/stock_list.csv` 显式保存查询 symbol。

### 理由与后果

它适合低成本个人项目，支持股票、ETF、指数和加密资产，能快速复用现有指标。代价是它并非交易所官方行情服务，上游结构、限流和可用性可能变化，不适合作为实时或交易级数据源。未来切换商业数据源时应保留标准化日线输入结构，并至少提供当前指标所需的 `trade_date/close/high/low`。

## ADR-002：保留静态 JSON 架构

- 状态：Accepted
- 日期：2026-09-14
- 关联需求：DATA-001, UI-001, OPS-002

### 决定

Python 定时生成 `public/data/dashboard.json`，React 只读取静态文件，GitHub Pages 托管构建产物。

### 理由与后果

无需服务器和数据库，部署简单且成本低。页面更新频率受工作流与上游日线更新时间限制，不提供实时刷新。

## ADR-003：长期指标严格使用 250/252 个数据点

- 状态：Accepted
- 日期：2026-09-14
- 关联需求：DATA-004, DATA-005

### 决定

MA250 只在至少 250 条有效记录时计算；52 周指标只在至少 252 条有效记录时计算。历史不足返回 `null`，但保留标的基础行。

### 理由与后果

这样不会把新股排除在看板之外，也不会用缩短的窗口冒充正式指标。前端和排序必须正确处理缺失值。

## ADR-004：由一次 yfinance 下载派生复权与未复权价格序列

- 状态：Accepted
- 日期：2026-09-14
- 关联需求：DATA-003, DATA-004

### 决定

只执行一次 `auto_adjust=False` 下载；未复权模式使用原始 `Close/High/Low`，复权模式按每日 `Adj Close / Close` 因子同比例调整这三个指标所需价格序列。`Open` 与 `Volume` 不属于 V1 JSON 契约。

### 理由与后果

避免只调整收盘价却用原始高低价计算 52 周区间，同时把每个标的的网络请求数减半，降低上游限流风险。复权数据可能考虑拆股和分红，与纯价格涨跌含义不同，UI 必须明确模式。

## ADR-005：以纽约时间管理生成任务

- 状态：Accepted
- 日期：2026-09-14
- 关联需求：DATA-006, OPS-001

### 决定

工作流按 `America/New_York` 工作日 22:30 触发；生成时间使用带偏移的纽约时间；另存 `data_date`。

### 理由与后果

纽约时区能自动处理夏令时，减少手工调整 UTC cron。GitHub Actions 可能延迟，且节假日仍可能触发；以实际 `data_date` 判断数据是否更新。

## ADR-006：文档是项目长期记忆

### 决定

## ADR-007：单一 CSV 管理多列表

- 状态：Accepted
- 日期：2026-09-18
- 关联：DATA-007、UI-002、CR-001

CSV 保持 code 唯一；watchlist=original 标记原列表，tier=A/B/C 标记新列表成员，可同时存在。新 ticker 按用户输入查询，不猜测替代代码；PSTG 已核实更名为 P，CR-002 已获用户确认，查询映射保留展示代码和同一公司；未提供公司名称的新条目以 ticker 显示。一次批量下载覆盖 133 个唯一代码。JSON 可选 collections 提供原列表、新列表和 A/B/C 的代码集合与分口径汇总；Python 计算汇总，React 只筛选和排序。旧 JSON 没有 collections 时仍展示原数据。没有新增依赖。

## ADR-008：显式配置停牌状态

- 状态：Accepted
- 关联：DATA-008、UI-003、CR-002

停牌由 CSV 显式维护，不从下载错误推断。独立 suspended 元数据使既有有效行情行字段保持不变；页面仅展示停牌身份，不计算或伪造指标。当前仅 CFLT，说明为已被收购并停止交易。若未来临时停牌恢复交易，应依据核实结果将 CSV trading_status 改回 active。无有效行情的发布保护不变。

## ADR-009：统一吸顶区域与静态页面路由

- 状态：Accepted
- 关联：UI-004、CR-003

使用 hash 路由 #/watchlist、#/research、#/research/A|B|C 实现独立列表视图和真实链接导航，无需新增路由依赖或 Pages rewrite。仅新增列表显示分档入口。指标选项、榜单标题和表头组合为正常占位的 sticky top:0 区域，放在横向表体容器外；双向同步 scrollLeft，并使用相同 grid 列宽。去掉原 top:72px 偏移以及混合升降序和区间分组，所有指标数值升序、缺失末尾、停牌最后。

## ADR-015：同一次部署内有限重试（CR-015 / OPS-004）
采用Python标准库wrapper；仅明确最新日线缺价返回75，每30分钟启动新进程，最多9次。无需新增依赖、PAT或actions:write，不递归触发workflow_run。代价是等待期间占用runner，最多4小时等待加生成时间，build超时300分钟。22:30是经验时间，不是Yahoo SLA。每轮证据保留，最终耗尽仍失败。

## ADR-016：确定性浏览器回归与发布前检查
- 状态：Accepted；关联CR-016 / UI-019 / NFR-003。
- Playwright用固定JSON拦截数据请求，覆盖导航、排序、图表、复制、异常与响应式布局，不依赖Yahoo。真实数据生成仍在部署build独立验证。
- checks.yml复用于PR与deploy，失败保存截图/trace 14天；deploy仅在检查通过后生成真实行情。未配置仓库分支保护，不将PR检查等同于强制合并规则。
- JSON入口校验关键结构，异常显示重试；exporter拒绝非有限数字，临时文件原子替换单个目标。不是多文件事务，生成失败不得部署。

## ADR-020：可比较的日均波幅
- CR-020 / DATA-024 / UI-023：使用三自然月逐日百分比真实波幅的算术均值，同时覆盖盘中及隔夜；不以美元ATR比较不同股价，不把年化波动率当每天的摆幅。
- 先百分比化再平均，避免末日价格改变过去幅度的基准；完整跨度且至少40样本，价格异常不忽略。默认复权、默认52周位置不变，独立波幅降序按钮。

## ADR-021：事件风险与财报分级分离
- CR-021 / DATA-025 / UI-024 / RES-008：独立研究文件覆盖三个列表并集，原始事件人工核实，关键词只作为候选。事实阶段、当前/历史/已解决、主体身份和原文链接分别保留。
- 无事件不显示绿色安全标志；披露范围与未穷尽边界见研究报告。主表股票下显示简短标记、弹窗看详情，箱体仅单股详情显示；不改选股名单或原分级。

## ADR-022：事件分层先于财务困境评分
接受。CR-022采用有原始证据的生存/上市事件汇总；不混用受限资金、客户资产及未提款授信，不用现金余额估算替代完整资金跑道。破产概率/持仓保证与自动删股不在范围。研究为静态人工快照，行情更新不改变研究日期。代价是不能把未触发事件解释为已经完成所有偿债能力核验，详情必须披露该覆盖边界。详见FINANCIAL_DISTRESS.md。

## ADR-023：情景估值以显式假设和独立快照发布

Accepted，CR-029 / DATA-030 / UI-029 / RES-013。情景合理价统一折现到逐只估值日，机构目标价独立参照；公司DCF/压力回收为首期计算模型，参数和来源人工研究后才可输入，计算仍只在indicators.py。CSV唯一成员来源，valuation_assumptions.json唯一假设入口，生成器原子输出valuation-scenarios.json v1；不新增付费服务或依赖。代价是大量成员初期保持待研究，不能从机构价或通用倍数直接自动补齐全池。月度研究日期不随每日行情推进，工程覆盖和真实估值覆盖分别报告。
